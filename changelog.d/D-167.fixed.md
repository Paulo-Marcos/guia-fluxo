- **O `ship` recusa marca de desbloqueio que a fila descartaria (D-167, épico E-011).** O rebase com que a fila atualiza a branch descarta commit vazio e merge; uma marca `[unlock:]` só neles sumia e o lock-check do PR reprovava (D-157). Agora o `ship` confere que cada marca necessária está num commit que muda arquivos e recusa antes do portão, dizendo como corrigir. Testes em `tests/test_ship_unlock_marks.py`. De quebra, as leituras do git em `_git_ops` passam a decodificar UTF-8: no Windows o codec padrão (cp1252) derrubava o ship com emoji no histórico (o byte 0x90 do 🐛).
